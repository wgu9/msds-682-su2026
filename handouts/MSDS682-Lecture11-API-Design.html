Without a status contract, clients may treat 202 as completion, retry the same work, or lose track of failures.

REST, FastAPI, and streaming design solve different problems

REST / HTTP
Defines how a client sends a request and receives a response.
method · path · status · representation
FastAPI
Implements routes, validation, lifespan, errors, and OpenAPI.
Python framework
Streaming API design
Defines the durable workflow behind the route and observable completion.
Kafka · worker · state · retry · result

REST defines the HTTP interface. FastAPI implements it. The streaming design defines processing, retry, and result lookup.
