# MSDS 682 Final Presentation Rubric

## Scope

The final presentation is worth **20% of the course grade**. This rubric grades
only the scheduled presentation and Q&A. The proposal and final written report
and code package are graded separately.

The base rubric contains **10 atomic criteria worth 2 points each**. It restates the
five-part story already published in the
[Final Presentation Requirements](#/handouts/final-presentation-requirements);
it does not add a new project requirement. Up to **3 optional bonus points** may
be earned for presentation-specific evidence beyond the required story.

For a two-person team, the project receives one shared presentation score. Both
students must speak, as stated in the published presentation requirements.

## Atomic Scoring Rule

Score every criterion independently:

- **2 points:** Clear, specific, internally consistent, and supported by the
  project or visible evidence when evidence is applicable.
- **1 point:** Identifiable and relevant, but materially incomplete, unclear,
  inconsistent, or weakly supported.
- **0 points:** Missing, contradictory, or not connected to the presented
  project.

Only content presented within the assigned slot and the one-minute Q&A is
scored. A live demo is optional. Visual polish alone, the number of tools, and
project complexity do not earn base points.

## Rubric: 20 Points

| # | Atomic criterion | Observable pass condition | Points |
|---:|---|---|---:|
| **1** | **Problem** | States one specific problem the project addresses. | 2 |
| **2** | **Target user or decision** | Identifies who needs the result or what decision the result supports. | 2 |
| **3** | **Data source** | Identifies where the data comes from. | 2 |
| **4** | **Event contract** | Shows or explains the event that enters Kafka, including the key or identifying fields needed by the system. | 2 |
| **5** | **Streaming architecture** | Traces the implemented path from source or replay through Kafka and processing to the output. | 2 |
| **6** | **Useful result** | Shows a visible end-to-end result and explains what it means. A recorded result or submitted artifact is acceptable. | 2 |
| **7** | **Validation or evaluation** | Shows a test, metric, acceptance check, comparison, or evaluation result that supports the project claim. | 2 |
| **8** | **AI role** | Defines the bounded task performed by AI or the AI-assisted workflow used in engineering the project. | 2 |
| **9** | **AI verification** | Explains how the AI output or AI-assisted work was checked. | 2 |
| **10** | **Lesson or next step** | Ends with one evidence-based lesson, current limitation, or proportional next step. | 2 |
|  | **Total** |  | **20** |

## Optional Presentation Bonus: Up to 3 Points

Apply the base 2, 1, or 0 scoring rule as **1, 0.5, or 0 bonus point**. Bonus
evidence must appear within the assigned presentation and Q&A slot. It cannot
replace a missing base criterion.

| Bonus criterion | Observable pass condition | Points |
|---|---|---:|
| **P1. Design tradeoff** | Identifies one credible alternative, names the constraint that shaped the choice, and explains why the implemented design was selected. | +1 |
| **P2. Evidence visualization** | Uses one accurate visual, table, or concise demonstration to connect a project claim to its result and validation evidence without relying on a code or file walkthrough. | +1 |
| **P3. Technical defense** | Answers the instructor's focused Q&A question accurately, connects the answer to project evidence, and states uncertainty when the submitted evidence does not support a stronger claim. | +1 |
|  | **Maximum presentation bonus** | **+3** |

The maximum raw presentation score is **23 points: 20 base points plus 3 bonus
points**.

## Delivery and Timing Rules

- **Individual:** 5 minutes presenting and 1 minute for Q&A; 6 minutes total.
- **Two-person team:** 7 minutes presenting and 1 minute for Q&A; 8 minutes
  total, with both students speaking.
- Presentations stop at the published end time so every project receives its
  full slot. Material not reached before the stop time is not scored.
- The one-minute Q&A is used for one focused question. A concise answer grounded
  in project evidence may clarify a rubric criterion.
- Do not walk through every file or read large blocks of code.
- The current project order and exact start times are published in the
  [Final Presentation Schedule](#/handouts/final-presentation-schedule).

Every score below 2 points should include a short note naming what was missing,
unclear, inconsistent, or unsupported.
